# ИУ Ассистент

Приватный Telegram-бот на **Go + SQLite + Ollama**. `bge-m3` строит эмбеддинги, Go
сравнивает их косинусным сходством, а `qwen3:8b` формулирует ответ по найденным
карточкам. Go проверяет ID источников и добавляет ссылки. Облачного ИИ и отдельной
векторной базы нет. Интернет нужен для Telegram и первой загрузки моделей.

## Быстрый запуск на Windows

Все команды выполняйте в PowerShell из папки проекта:

```powershell
cd "$HOME\Desktop\IU-Assistant"
Copy-Item .env.example .env
notepad .env
```

Если `.env` уже есть, **не перезаписывайте** его. Заполните:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_OWNER_ID=ваш_числовой_Telegram_ID
```

Не вставляйте секреты в переписку, исходный код и скриншоты.

Если ID неизвестен, заполните токен Telegram, остановите другие экземпляры бота,
выполните `.\start.ps1 whoami` и отправьте боту личное сообщение.
Команда выводит только ID, не текст. Внесите свой ID в `.env`.
**Не выбирайте ID другого человека из списка.**

Установите и запустите [Ollama](https://ollama.com/download/windows), затем:

```powershell
ollama pull bge-m3
ollama pull qwen3:8b
.\start.ps1 import
.\start.ps1 doctor
.\start.ps1 run
```

Чтобы пересчитать эмбеддинги по текущим карточкам SQLite без повторного импорта
JSON, используйте `.\start.ps1 reindex`. Команда не меняет историю. `doctor` проверяет Telegram,
наличие моделей и индекс. Для проверки ответа:

```powershell
.\bin\iu-bot.exe ask "Где найти учебные материалы ИУ?"
```

`OLLAMA_URL` по умолчанию `http://127.0.0.1:11434`. Не открывайте этот адрес
наружу. Первый запрос после запуска модели может быть медленнее обычного.

После настройки можно запускать двойным кликом `start.cmd`. Остановка — Ctrl+C.
Компьютер должен быть включён, программа открыта, Интернет доступен.
Запускайте только один экземпляр; webhook для этого бота должен быть отключён.

### Если PowerShell запрещает запуск скрипта

Используйте `start.cmd` или запускайте готовый файл из корня проекта:

```powershell
.\bin\iu-bot.exe validate
.\bin\iu-bot.exe import
.\bin\iu-bot.exe run
```

## Что реализовано

- Только личные сообщения от владельца; чужие пользователи и группы игнорируются
  **до обращения к модели**. Без owner ID запуск запрещён.
- Один локальный векторный поиск для чата и меню. Меню ограничивает область
  поиска, а явно указанные ФИО, кафедра и год учитываются отдельно.
- Готовые вопросы и названия имеют точное текстовое сопоставление.
- Поиск преподавателя по фамилии, выбор однофамильца кнопкой.
- Генерация по выбранным справочным записям, проверка ID источников.
- Ссылки и даты берутся из базы, а не из сгенерированного текста.
- Приветствия, помощь, благодарности и простые уточнения обрабатываются без ИИ.
- Главное меню с разделами, навигация назад и кнопки выбора типа документа.
- Различаются непонятный запрос, посторонняя тема, отсутствие подтверждённых
  сведений и временная ошибка сервиса — с понятным следующим шагом.
- Уточнение вопроса, если найденной информации недостаточно для выбора.
- Ограниченная история SQLite, сохранение после перезапуска, `/reset`.
- Отправка локальных оригинальных файлов с проверкой SHA-256.
- Валидация JSON, резервная копия индекса, транзакционное обновление.
- Временные ошибки Telegram не завершают программу; повтор с задержкой.

При сетевой ошибке/некорректном ответе модели выводится отдельное сообщение
о недоступности, а не ложное утверждение, что сведений нет. Для точного выбора
одной записи при сбое ИИ возможен ответ её исходным текстом.

**RAG снижает, но не устраняет галлюцинации.** Проверка ID и формата не доказывает
верность каждого предложения. Сгенерированные ответы нужно проверить на своих
вопросах; важные сведения сверять с источниками.

## Стартовая база и реальные ограничения

`knowledge/base.json` уже наполнен. Карточки кафедр охватывают ИУ1–ИУ10;
ИУ11 выделена как отраслевая подготовка по перечню ЭОС, а не как утверждение
о текущей организационной структуре факультета.

### Подробный раздел ИУ6

18.11.2026 база расширена до **652 записей (651 опубликована)**. Все 267 прежних
записей, кроме дополненного обзора ИУ6, сохранены без изменений. Данные по
университету и другим кафедрам не заменены данными одной кафедры.

Для ИУ6 собраны:

- **36 именных страниц/ссылок преподавателей** — с биографией, публичными
  профессиональными контактами и дисциплинами только там, где они открыто указаны.
- **166 карточек курсов**, включая отдельный курс оформления практики.
- **155 библиографических карточек** с авторами, годом, дисциплиной и ссылкой.
- **11 ссылок на документы ГЭК/ВКР**, сохранённые локально с SHA-256
  (среди них есть повторяющиеся PDF из бакалаврского и магистерского разделов).
- Контакты кафедры, рабочий портал, программы и лаборатории, указатели практики,
  учебных планов, ВКР и расписания.

Основной полезный источник — **https://e-learning.bmstu.ru/iu6/**, хотя отдельный
`iu6.bmstu.ru` на дату проверки ограничен. Каталог и библиотека открыты, но часть
занятий, практика и расписание требуют университетский вход. Вход не обходится.

Это не полный проверенный кадровый список: часть страниц пустая, историческая
или переименована. Различия имён в меню и каталоге помечены. Совпадения ФИО
в публикациях разных кафедр сохраняются отдельными карточками с указанием кафедры,
а не автоматически объявляются разными/одинаковыми людьми.

Каталог содержит **разные годы, уровни и даже группы других кафедр** — он не
является учебным планом конкретного студента. Библиотека представлена метаданными
и ссылками, а не полными текстами/готовыми решениями. Списки студентов на защитах,
оценки, закрытые задания и чужие персональные кабинеты не собираются.

В меню есть **«Моя кафедра — ИУ6»** и отдельный **«Университет»**. Каталоги
преподавателей, курсов и книг перелистываются страницами. Выбор карточки показывает
проверенный исходный текст и ссылки **без запуска модели**. Запросы на ссылки и
материалы ИУ6 также могут сразу предлагать карточки вместо генерации.

Добавлены опубликованные списки преподавателей **ИУ1, ИУ3, ИУ7, ИУ8**,
отдельные сведения о руководстве ИУ9 и ИУ10, учебные ресурсы и справочные
записи о заявлениях. В некоторых карточках ИУ3 источник публикует только
инициалы — полное имя не додумывается.

**Это НЕ полный список всех преподавателей, ведущих на ИУ.**
Состав преподавателей других подразделений, ведущих у конкретных групп,
требует подтверждённого расписания и дальнейшего наполнения. Страницы факультета
и часть кафедральных ресурсов на дату проверки были ограничены или недоступны.
Опубликованный кафедрой список может устареть независимо от даты нашего чтения.

### Документы ВКР и шаблоны заявлений

Для ВКР ИУ6 найдены официально опубликованные файлы, но их годы требуют внимания:
положение о ГИА — **редакция 2017**, положение о нормоконтроле — **редакция 2016**,
часть шаблонов содержит **2020**. Ссылка находится в разделе ГЭК 2026, но это
не делает документ редакцией 2026 и не подтверждает применимость к защите 2027.
В магистерском разделе образец рецензии фактически относится к бакалаврской
работе — это явно отмечено. Старые даты и подписантов нельзя подавать как готовые
актуальные документы.

**Актуальные бланки заявлений ИУ на отчисление/академический отпуск по-прежнему
не подтверждены.** Бланки ВКР их не заменяют. В комплекте также есть официальный
PDF общеуниверситетского положения 2026 года, но это не бланк заявления.

Найденный старый образец отчисления ГУИМЦ содержит устаревшее имя ректора;
он сохранён как `archived` для аудита и **не попадает в поиск или выдачу**.
Бот не подменяет формы ИУ документами другого подразделения.
Для завершения наполнения нужны действующие файлы/ссылки от деканата ИУ.

Информация о справке об обучении отделена от справки о периоде обучения.
Локальные сроки и сотрудники ГУИМЦ не приписываются ИУ.

## Команды Telegram

После `/start` под строкой ввода появляются быстрые кнопки: **ИУ6**,
**Университет**, **Материалы** и **Документы**. Вы по-прежнему можете набрать
вопрос вручную или использовать кнопки под отдельными сообщениями.

«Материалы» открывает каталог и не ограничивает следующий вопрос. Чтобы искать
только по курсам, пособиям, практике, ВКР и документам ИУ6, нажмите «Искать в
материалах ИУ6». Ограничение действует на одно сообщение, его можно отменить.
Если совпадений нет, кнопка «Поискать по всему справочнику» повторяет исходный
вопрос без ограничения по разделу.

| Команда | Назначение |
|---|---|
| `/start`, `/menu` | Знакомство и главное меню |
| `/help` | Возможности, примеры и ограничения |
| `/iu6` | Подробный раздел своей кафедры |
| `/university` | Общие сведения и сервисы МГТУ |
| `/materials` | Открыть раздел материалов ИУ6 |
| `/departments` | Кафедры с кнопками |
| `/teachers Иванов` | Поиск по имени/фамилии |
| `/resources` | Полезные ресурсы |
| `/documents` | Меню справок и заявлений |
| `/files` | Добавленные официальные файлы |
| `/reset` | Очистить локальную историю |
| `/privacy` | Обработка данных |

На первом экране есть быстрый поиск преподавателя и материалов. Нажмите кнопку
и напишите фамилию, ФИО или короткое название предмета. Этот поиск работает
локально и показывает карточки без генерации. Чтобы выйти из
поиска, нажмите «Назад» или отправьте `/menu`.

Разделы и страницы каталога обновляются в том же сообщении. Из карточки можно
вернуться к списку, открыть источник или курс напрямую. При просмотре карточки
документа бот сначала показывает описание и оговорки, затем позволяет запросить
файл кнопкой «Прислать файл». Длинные карточки могут прийти отдельными сообщениями.

Можно писать обычным текстом, например:

- `Привет`, `Что ты можешь?`, `Спасибо`
- `Контакты ИУ6`, `Как связаться с Ерёминым ИУ6?`
- `Материалы по базам данных ИУ6`, `Пришли шаблон ТЗ ИУ6`
- `Нужна справка` — бот уточнит её тип и предложит кнопки
- `ИУ7`
- `Кто такой Рудаков?`
- `Как связаться с ИУ9?`
- `Где найти учебные материалы?`
- `Как подать заявление на отчисление?`
- `Пришли положение об академическом отпуске`
- После карточки преподавателя: `А какая у него почта?`

Для поиска фамилии предпочтителен именительный падеж.
Частые однозначные склонения вроде «Ерёминым» и «Ивановой» также распознаются.
Неоднозначные формы и однофамильцы требуют выбора; имя не угадывается по похожести.

### Как устроен диалог

1. Короткие стандартные реплики обрабатываются локально, без API и расхода
   токенов. Приветствие перед вопросом не скрывает сам вопрос.
2. Для неоднозначных «нужна справка» и «хочу написать заявление» бот задаёт
   уточнение. Можно нажать кнопку или ответить текстом, например «для перевода».
   Уточнение сохраняется в истории своего пользователя; `/reset` его очищает.
3. Конкретный вопрос идёт в поиск по базе. Qwen формулирует ответ только
   по найденным записям; программа проверяет ID источников и добавляет ссылки.
4. После подтверждённого ответа программа сохраняет ID использованных записей
   вместе с историей пользователя. Реплика «а его почта?» привязывается к
   последней подтверждённой карточке без угадывания имени моделью. Если карточек
    несколько, бот предлагает выбрать. При отсутствии такой привязки бот
    просит уточнить тему. Явно названные новая
   кафедра или преподаватель имеют приоритет над прошлой темой.
   Приветствия и благодарности не вытесняют справочный контекст.
   Уже самостоятельный вопрос передаётся на генерацию без лишней истории
   предыдущих тем, чтобы не смешивать их источники.
5. Если поиск ничего не нашёл, бот сообщает об отсутствии подтверждённых сведений,
   не запрашивая ответ у модели.

Бот не является универсальным собеседником или поисковиком по Интернету.
При отсутствии информации он не заменяет источники «знаниями» модели.
Если подтверждённого ответа нет, кнопка «Искать на сайтах МГТУ» открывает
Google с фильтром `site:bmstu.ru`. В ссылку попадают только заранее заданные
общие ключевые слова, не ваш вопрос или история. Результаты открываются в
браузере и не сохраняются в справочник.
При недоступности Ollama приветствия, меню и локальные уточнения продолжают
работать; для точного выбора одной записи возможна выдача её исходного текста.
Такая же безопасная выдача используется, если ответ на точный выбор карточки
не прошёл проверку формата или ID источников; сама проверка не отключается.

## Управление базой

1. Найдите официальный источник и убедитесь в его актуальности и применимости.
2. Добавьте/отредактируйте запись в `knowledge/base.json`.
3. Для нового материала сначала используйте `status: "draft"`.
4. Проверьте содержание, источник, цитату и дату; измените статус на `published`.
5. Выполните `validate`, затем `import`.

Пример:

```json
{
  "id": "my-record",
  "kind": "faq",
  "title": "Название темы",
  "aliases": ["Вариант вопроса", "Перефразировка"],
  "body": "Проверенный ответ. Не добавляйте отсутствующие в источнике факты.",
  "scope": "Факультет ИУ",
  "status": "draft",
  "sources": [{
    "title": "Название официальной страницы",
    "url": "https://example.org/replace-with-real-source",
    "checked_at": "2026-11-17",
    "quote": "Подтверждающий фрагмент"
  }]
}
```

Разрешённые типы: `department`, `teacher`, `resource`, `faq`, `template`.
Статусы: `draft`, `published`, `archived`. Идентификаторы — латиница, цифры,
дефис/подчёркивание, до 62 символов; должны быть уникальны.
Неизвестные JSON-поля и ошибки источников блокируют импорт.

Для файла добавьте к опубликованной записи:

```json
"attachments": [{
  "name": "Официальный бланк: название",
  "file": "my-form.docx",
  "source_url": "https://example.org/replace-with-real-file-url",
  "sha256": "замените_64_шестнадцатеричными_символами"
}]
```

Положите оригинал в `knowledge/files/`. Хеш:

```powershell
Get-FileHash knowledge/files/my-form.docx -Algorithm SHA256
```

Файлы должны быть обычными файлами до 20 МБ. Форматы: PDF, DOC, DOCX, ODT,
RTF, XLSX. Переходы за пределы каталога и символьные ссылки наружу запрещены.
Файл отправляется только после выбора кнопки скачивания в карточке.

SQLite — единственная рабочая база. `base.json` — набор данных для начального
заполнения и пакетных обновлений, бот не читает его при ответах.
`import` переиспользует эмбеддинги неизменённых текстов.
Изменение только источника не требует пересчёта вектора. `reindex` пересчитывает
все векторы. При ошибке старая рабочая база остаётся. Перед заменой сохраняется
полный предыдущий индекс в `data/backups/index-*.json`.
JSON редактируется до импорта, поэтому его собственные версии сохраняйте отдельно.

После успешного импорта работающий бот видит новую базу на следующем вопросе.
Перед сменой `.env` остановите и запустите **этого бота** заново.

### Извлечение преподавателей

#### ИУ6: безопасное дополнение существующей базы

Новый сборщик использует открытые страницы, сохраняет снимки, проверяет файлы
и по умолчанию создаёт только черновой отдельный результат:

```powershell
go run ./cmd/collect-iu6 -snapshots data/snapshots/iu6-YYYYMMDD -out knowledge/iu6-new.draft.json
```

После проверки карточек, отчёта `*.report.json`, годов документов и ограничений
доступа можно повторить разбор снимков без сети:

```powershell
go run ./cmd/collect-iu6 -offline -reviewed -checked YYYY-MM-DD -snapshots data/snapshots/iu6-YYYYMMDD -out knowledge/iu6-new.reviewed.json
```

`-checked` — дата фактической проверки, не придуманная новая дата старого снимка.
`-apply` допускается только с `-reviewed`, сохраняет копию исходного `base.json`
и проверяет, что файл не изменился во время сбора. Коллизии ID уже добавленных
карточек запрещают автоматическую перезапись: повторное обновление требует
сравнения с ручными правками, а не запуска с удалением старой базы.

Ручные обзорные карточки — `knowledge/iu6-curated.json`. Закрытые страницы
не извлекаются. Веб-страницы и файлы остаются данными, не исполняются.

#### Остальные кафедры

Дополнительная утилита на Go создаёт **отдельный** файл, а не меняет рабочую базу:

```powershell
go run ./cmd/collect -fetch -out knowledge/new.draft.json
```

Источники фиксированы в `cmd/collect/main.go`. Они скачиваются без входа
в кабинеты; страницы с ограниченным доступом не обходятся.
Текст извлекается без генерации биографии, статус карточек по умолчанию `draft`.
Снимки страниц — в `data/snapshots`. Дата снимка используется как дата чтения.
При изменении разметки утилита останавливается, а не публикует пустой результат.

`-reviewed` разрешён только после ручной проверки соответствующих снимков.
Утилита объединяет базовые записи из `knowledge/curated.json` с извлечёнными.
Она **не переносит ваши ручные правки** из `knowledge/base.json`:
не подменяйте им рабочий JSON без сравнения.
Это относится и к дополнению ИУ6/общеуниверситетским карточкам: старый сборщик
начинает с `curated.json` и не должен использоваться для их перезаписи.
Уже существующий выходной файл не перезаписывается.

## Команды консоли

```powershell
.\bin\iu-bot.exe validate
.\bin\iu-bot.exe import
.\bin\iu-bot.exe reindex
.\bin\iu-bot.exe stats
.\bin\iu-bot.exe search "Где найти учебные материалы?"
.\bin\iu-bot.exe ask "Где найти учебные материалы?"
.\bin\iu-bot.exe doctor
.\bin\iu-bot.exe run
```

`ask` использует отдельную историю с user ID = -1, не смешивая её с Telegram.
`search` показывает найденные ID и оценки без генерации и записи истории.

## Сборка и тесты

Для исходников нужен Go **1.26+**; готовый Windows EXE запускается без Go.
Первая сборка загружает зависимости, C-компилятор не нужен: SQLite — pure Go.

```powershell
.\build.ps1
# или
go test ./...
go vet ./...
go build -trimpath -o bin/iu-bot.exe ./cmd/iu-bot
```

Обычные тесты не требуют ключей и не обращаются в реальные Telegram/Ollama:
используются локальные HTTP-серверы и подставные ответы.
Проверяются импорт, повторное использование векторов,
отказ при чужих источниках, поиск однофамильцев, резервирование,
транзакции, сохранение/очистка памяти, доступ владельца и защита файлов.
Также проверяются миграция прежнего индекса, простые русские окончания, отказы на посторонние вопросы
и выдача по контрольным вопросам реальной базы.
Проверяются также приветствие с вопросом, отсутствие API-вызовов при простом
общении, выбор документа кнопкой и текстом, смена темы, продолжение разговора,
устаревшие кнопки, авторизация всех типов callback,
сохранение контекста после «спасибо» и очистка уточнения через `/reset`.
Для ИУ6 проверяются сохранность общеуниверситетских сведений, покрытие каталогов,
поиск контактов/материалов, выбор кафедры при совпадающем ФИО, страницы меню,
просмотр исходной карточки без API и предупреждения о старых редакциях файлов.

Контрольные вопросы для ручной проверки — `knowledge/evaluation.json`.
Воспроизводимое сравнение с прежним BM25 (только в тестах):

```powershell
$env:IU_EVAL_DB = (Resolve-Path data/bot.db).Path
go test -v -count=1 ./internal/assistant -run '^TestRetrievalComparison$'
```

`MIN_SIMILARITY` — порог косинусного сходства. Не снижайте его без проверки
ложных совпадений на вопросах вне базы.

На контрольном наборе из 20 запросов при пороге `0.53` нужная карточка попала
в первые три результата в **12 из 14** случаев против **2 из 14** у BM25.
На шести запросах без ответа оба метода не выдали ни одной карточки.
Это проверка поиска на небольшом наборе, а не оценка точности всех ответов Qwen.

## Архитектура

```text
cmd/iu-bot       команды и запуск
cmd/collect      подготовка черновиков из публичных списков
internal/config .env и проверка настроек
internal/ollama локальные эмбеддинги и генерация
internal/knowledge JSON, источники, вложения
internal/store  SQLite, резервирование, история
internal/assistant векторный поиск, уточнение, проверка ответа
internal/telegram long polling, доступ, кнопки, файлы
knowledge/      редактируемые материалы и оригиналы документов
data/           локальная рабочая БД, снимки, резервные копии
```

Модель получает до трёх подходящих записей. История связана с ID карточек и используется для понимания
продолжений, но не считается источником фактов. Хранится только последние
`HISTORY_PAIRS` пар (по умолчанию 5), а не бесконечный журнал.

## Приватность и ограничения

- Поиск и генерация работают локально. Сообщения бота проходят через Telegram.
- `.env` и `data/` не публикуйте. SQLite содержит текст истории.
- `/reset` удаляет историю логически из локальной БД, не сообщения в Telegram
  и не гарантирует физическое стирание с диска.
  Вместе с историей удаляется сохранённая тема (ID последних подтверждённых записей).
- Логи не содержат токенов, запросов и ответов пользователей.
- Long polling не требует открывать порты. После аварии между отправкой ответа
  и сохранением offset возможно повторное сообщение (at-least-once).
- Веб-поиска во время ответа, доступа в ЛКС, персональных оценок и автоматического
  заполнения заявлений нет.
- Это учебный помощник, не официальный бот факультета и не замена деканату.
